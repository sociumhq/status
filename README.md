# Socium status

Внешний мониторинг сервисов Socium. Каждые 5 минут GitHub Actions проверяет адреса из
[`checks.json`](checks.json) со своих серверов, поэтому мониторинг работает, даже если лежат все наши серверы.

Плановый запуск `*/5` GitHub выполняет редко (19.11.2026 — раз за 13 часов), поэтому одна задача проверяет каждые
5 минут почти шесть часов и сама запускает следующую. Почасовое расписание только поднимает цепочку, если она
оборвалась; задача, закончившаяся быстрее 30 минут, следующую не запускает (защита от бесконечного перезапуска).

| Проверка | Адрес | Важность |
| --- | --- | --- |
| Проверка лицензий через прокладку | `https://licenses.thredium.app/health` | критично |
| Сервер лицензий готов (база, Redis, worker) | `https://licenses.thredium.app/api/v1/health/ready` | критично |
| Сайт | `https://thredium.app/` | важно |
| Кабинет | `https://app.thredium.app/` | важно |

## Как сообщает

- Проверка не прошла два раза подряд (через 20 секунд) → открывается issue с меткой `incident` и сообщение в Telegram.
- Снова работает → issue закрывается с длительностью простоя и сообщение «снова работает».
- Открытые issue = текущие сбои, закрытые = история.

## Telegram

Нужны два секрета репозитория (Settings → Secrets and variables → Actions):
`TELEGRAM_BOT_TOKEN` — токен бота, `TELEGRAM_CHAT_ID` — чат или канал, куда он пишет. Без них работают только issue.

## Добавить проверку

Строка в `checks.json`: `id`, `name`, `url`, `expect_status`, `critical`. Секреты и внутренние адреса сюда не кладём:
репозиторий публичный.

Между концом одной задачи и стартом следующей проходит около минуты. Если цепочка оборвалась, следующий запуск
— в :17 ближайшего часа (по расписанию GitHub, которое может опаздывать).
